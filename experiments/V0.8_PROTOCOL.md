# V0.8 Experimental Protocol — Source-Executed Adapter Semantic Preservation

## Research question

Do the explicit V0.7 scalar adapters preserve the observable business semantics of the
exact locked external source methods from which they were derived?

## Reference execution

The reference implementation is extracted directly from the external source AST at the
commit frozen by V0.6.2. The selected method body is compiled without manually rewriting
its business decision expression.

Only environmental dependencies are stubbed. OpenFisca entity lookups return scalar harness
values and scalar equivalents are supplied for `not_` and `max_`. Django-Oscar object and
basket context is replaced by controlled objects exposing only the interface consumed by
the selected original method.

## Validation domains

- Apprenticeship tax: both Boolean inputs, exhaustive.
- Housing tax: boundary Cartesian product plus 20,000 deterministic random integer pairs
  in [0, 1,000,000], seed 20260926.
- Oscar partial satisfaction: all pairs for num_matches in [0,128] and required_count in [1,64].
- Oscar satisfaction: same grid, executing the original loop on multiple basket partitions.

## Acceptance criteria

For every correct adapter: zero mismatches.
For every deliberately wrong mutant: at least one mismatch.
All external checkout commits must equal the V0.6.2 lock commits.

The mutant experiment is a harness-sensitivity control, not an external-defect claim.
