# V0.5 Experimental Protocol — Rare-Witness Challenge

## Objective

Break the ceiling effect observed in V0.4, where BIZPROOF, Hypothesis, and CrossHair all detected every mutant.

V0.5 evaluates rare-witness business-rule defects under explicit analysis budgets.

## Benchmark

- 30 fixed rules;
- 10 banking;
- 10 e-commerce;
- 10 insurance;
- 6 challenge families;
- one correct implementation per rule;
- one rare-witness mutant per rule;
- 60 total cases.

The benchmark is versioned and fixed before execution.

## Challenge principle

Each mutant differs from the reference rule on a very small fraction of its input domain.

The benchmark records:

- exact bounded-domain size;
- analytically known witness count;
- witness density.

## Methods

### BIZPROOF

One symbolic verification run per case.

A correct case may be reported as `PROVED` only when the BIZPROOF backend produces a formal proof under the supported semantics.

### Hypothesis

Search budgets:

- 100 examples;
- 1,000 examples;
- 10,000 examples.

Failure to find a counterexample is inconclusive.

### CrossHair

Per-condition symbolic-analysis budgets:

- 0.5 CPU seconds;
- 2.0 CPU seconds.

Failure to report a counterexample is inconclusive.

## Primary metrics

- mutant detection rate by budget;
- proof rate on correct cases;
- false-alarm rate;
- inconclusive rate;
- runtime;
- witness density.

## Interpretation

V0.5 is not intended to show that property-based testing is generally inferior. It tests a specific setting where business violations occupy a sparse region of the input domain.

The principal scientific question is whether evidence-carrying symbolic validation provides stable conclusions when counterexample search becomes budget-sensitive.


## Oracle isolation

V0.5 defines its own reference semantics.

The Hypothesis baseline and the CrossHair harness are constructed directly from the V0.5
reference expression. They do not reuse the V0.3 business-rule oracle.

This separation is required because V0.5 introduces challenge families that are not part of
the V0.3 benchmark.
